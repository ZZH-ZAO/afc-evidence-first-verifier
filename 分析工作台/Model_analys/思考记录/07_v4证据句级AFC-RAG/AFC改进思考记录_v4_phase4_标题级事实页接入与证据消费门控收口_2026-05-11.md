# AFC v4 Phase4 标题级事实页接入与证据消费门控收口（2026-05-11）

## 基于什么架构

继续基于 `受控 Search Tool + authority-first 入口 + Evidence Page Contract + Page Role Contract + Evidence Consumer Gate + 双通道裁决`。

本轮没有新增 provider，没有合并 `solve_submit.py`，也没有引入 LLM 终判。核心思路是：如果官方/权威检索结果的标题本身已经包含 `主体 + 时间 + 指标 + 数值/结果`，它不应该被当作普通入口页反复下钻，而应该作为受控的 `evidence_page` 候选进入消费链。

## 实现了什么

### 1. official_discovery 不再天然只能做入口

以前 `official_discovery` 即使找到了“4月1日人民币对美元中间价报6.9025 上调169个基点”这类标题事实，也会被 `evidence.py` 的 discovery-only 规则挡在摘要消费之外。

这轮改为：

- `official_discovery` 默认仍是 discovery-only；
- 只有当它已经被 `Page Role Contract` 判定为 `evidence_page` 且 `evidence_page_ready=true` 时，才允许进入摘要与候选句消费；
- page role 字段会从 retrieval item 传到 point/candidate，避免消费层看不见页面角色。

### 2. 标题级事实页进入 Evidence Page Contract

新增标题级事实页识别：

- 数值类：标题/摘要必须包含同一指标、数值、变动或报价形态；
- 日期/日程类：必须是通知、公告、安排、日历、休市/开市这类页面；
- event_result 类：必须有比分、赛果、战报、结果类形态；
- 数值类如果标题中出现日期，必须和 claim 的时间位点对齐，防止 `4月15日` 冒充 `4月1日`。

同时修掉一个误判：英文 `Report` 里的 `报` 不能再触发中文“报价/报数值”的事实页规则。

### 3. 日历/休市类不再把公告发布日期当事实日期

对 `market_calendar` claim 增加保护：

- 如果只是公告发布日期与 claim 日期不一致，不能直接形成 `date_mismatch`；
- 只有同一日历事实位点形成状态冲突时，才允许进入 refute；
- 否则只作为 `date_reference` 诊断保留。

### 4. official discovery 查询种子更高精度

把以下字段前移到官方发现 query：

- `core_binding.subject_entity`
- `core_binding.time_scope`
- `core_binding.object_entity`
- `core_binding.status_or_result`
- `source_strategy.must_have`
- `page_intent.must_contain`
- `direct_evidence_need.must_include`

目的不是多搜，而是让官方发现优先搜“必须能裁决的事实位点”。

## 解决了什么

本轮解决了一个关键断点：**证据不是完全抓不到，而是抓到了以后被 discovery-only / entry_page 老规则挡在消费链外。**

验证中已经看到：

- `afc_0008` 至少 1 个 claim 进入 `evidence_page=true / allowed_evidence_page / stable_direct_point`；
- `afc_0002` 继续稳定为 `1`；
- `afc_0008 / afc_0010` 没有因为放开消费而误抬标签；
- `afc_0001` 在修掉公告发布日期误判后回到 `2`，没有因为标题事实页规则被误判为错误。

## 还卡在哪

还没有达到“关键证据成功率打通”的最终停点。

当前主要卡点已经从“入口失败”变成两层：

1. **官方发现仍不稳定**
   - `afc_0010 c2` 有时能拿到 4月1日中间价标题事实页，有时只拿到 SAFE 入口页、旧年新浪页或泛页。
   - high-specific query 已经进入，但搜索源返回仍有波动。

2. **numeric point grounding 还会选错 claim_value**
   - 对 “4月1日中间价 6.9025、上调169个基点” 这类 claim，当前 numeric summarizer 仍可能把日期里的 `4` 当成 claim_value。
   - 这会导致候选句已经相关，但 point 不能稳定闭合。

3. **时延没有完全收住**
   - `phase4_titlefact6` 平均 retrieve 仍偏高。
   - 说明 official discovery / Playwright rescue / detail fetch 还需要更强的早停和 ROI 裁剪。

## 现有方案还能不能继续解

能继续解，不需要马上外部检索。

原因是失败层已经可解释：

- 如果搜不到精确页，是 `official_discovery query seed / source order / source health` 问题；
- 如果搜到了但不消费，是 `Page Role Contract / discovery-only / Evidence Consumer Gate` 问题，本轮已打通一部分；
- 如果消费了但不能裁决，是 `numeric point grounding` 的 slot 选择问题；
- 如果耗时高，是 `official discovery + rescue` 的 ROI 和早停问题。

这些都仍在现有架构范围内。

## 如果不能，再去外部检索

只有当下一轮完成以下两件事后仍无提升，才进入外部检索：

1. numeric point grounding 明确使用 `evidence_need_program.decision_slots.object/status_or_result`，不再从日期数字里选 claim_value；
2. official discovery 对 high-specific seed 做结果级打分和早停，优先保留同日期、同数值、同指标页面。

如果这两步后 `afc_0010` 仍稳定拿不到可裁决页，才去查 2026 最新的 hosted search / grounding / browser-agent 做法。

## 本轮验证结论

本轮属于“证据消费链打通一段，但未完成最终效果验收”。

已达成：

- `official_discovery -> evidence_page -> evidence_sentence_candidate` 的老断点被打通；
- 泛页、入口页仍不会直接推动标签；
- `afc_0008 / afc_0010` 未误抬；
- `afc_0001` 没有继续被错误公告日期误伤。

未达成：

- `afc_0010` 的关键中间价证据还没有稳定进入 direct point；
- retrieve 平均耗时仍不理想；
- numeric claim 的 point grounding 还需要下一刀。

## 下一步建议

下一轮不要继续泛调 query，而是进入 `numeric point grounding`：

1. 从 `evidence_need_program.decision_slots` 读取：
   - `object = 6.9025`
   - `status_or_result = 上调169基点`
   - `time_scope = 2026-04-01`
2. numeric summarizer 选择 claim_value 时优先选 object/status 数值，禁止把日期数字当 claim_value。
3. 对候选证据句做同位点检查：
   - 同日期
   - 同指标
   - 同数值
   - 同变动口径
4. 只有 point grounding 过关后才允许进入 direct point。
5. 同时给 official discovery 增加 ROI 早停：同日期同数值命中后停止继续救援同类 source。

## 项目动机记录

### 分类

证据链、Workflow、测试与回归

### 这次要做什么

把“官方发现页只能当入口”的老规则改成“只有通过页面角色合同的官方发现事实页才能进入消费链”，同时修掉标题级事实页的时间错配和公告发布日期误判。

### 动机是什么

项目现在的主要瓶颈不只是搜不到，而是搜到了可疑似裁决的材料以后，系统要么把它当入口页丢给下钻，要么因为老的 discovery-only 规则不让它进入候选句。这样会造成用户看到“好像搜到了”，但最终 reason 仍说没有 ready material。

### 对我们的项目有什么实际作用

这让 AFC 的证据链更接近真实 fact-checking 流程：页面先分角色，再决定能不能消费。官方标题事实页可以被消费，泛页和入口页仍被挡住。

### 具体场景又是什么

例如“4月1日人民币对美元中间价报6.9025，上调169个基点”这类题，搜索结果标题本身就可能是权威事实句。系统应该允许它进入证据候选，但不能让“4月15日”或“公告发布日期”冒充目标事实。

### 我应该怎么去使用

后续看 debug 时重点看：

- `title_level_fact_evidence_ready`
- `title_level_fact_evidence_reason`
- `page_role`
- `direct_evidence_gate_result`
- `point_conversion.slot_review_outcome`

如果页面已经是 `evidence_page` 但 point 没闭合，就不要再回到入口层改 query，应该看 numeric grounding。

### 对用户意味着什么

用户会更少看到“明明搜到标题事实却最后说没证据”的情况；系统也不会因为泛页和入口页多而轻易误判。

### 对开发者意味着什么

开发者之后排查失败时能区分：是搜索没命中、页面角色没过、候选句没生成，还是 point grounding 选错了值。

### 当前结论

标题级事实页消费链已经接上，但关键数值证据还没有稳定闭合。下一步必须优先修 numeric point grounding。

### 下一步建议

实施 `numeric point grounding by decision_slots`，先解决日期数字污染 claim_value，再回测 `afc_0010`。
