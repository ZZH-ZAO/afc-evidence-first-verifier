# AFC v4 Phase4 CR8：回归统计与下一步瓶颈定位

日期：2026-05-13

## 分类

测试与回归 / 证据链 / Workflow

## 这次看什么

这轮不是继续加功能，而是看 CR5-CR7 落地后，链路里到底还有哪一层最卡。

## 回归结果

我跑了 `sample_data_subset_3`，得到三条结果：

```text
afc_0001 -> 1-次需存在事实错误
afc_0008 -> 2-无事实错误
afc_0010 -> 2-无事实错误
```

从 debug 里能看到：

- `decision_policy_debug` 已经稳定写回 ledger。
- `decision_policy_route` 已经可见。
- `reason_builder` 已经开始输出自然 reason，而不是工程状态词。

## 现阶段最清楚的信号

现在的瓶颈不再是“policy 看不见”，而是：

```text
candidate_unconverted
-> direct_supported / direct_refuted
```

这条转换还不够稳。

也就是说，很多样本已经拿到了候选材料和风险形态，但仍没有稳定进入“同槽直裁”或“可授权风险补判”。

## 基于什么架构

基于前面已经搭好的链路：

```text
candidate/page/point
-> evidence_event
-> phase_graph
-> decision_state
-> decision_policy
-> reason_builder
```

CR8 不是改这条链，而是判断它现在卡在哪一跳。

## 实现什么

这轮统计的结果说明：

1. `decision_policy` 已经能稳定作为兜底权限出口。
2. `reason_builder` 已经能给出自然解释。
3. 但仍有大量样本停在 `candidate_unconverted`，说明“证据事件 -> 可裁决点”的转换率仍然是下一层短板。

## 解决什么

这一步解决的是“知道哪一层该补”的问题：

- 不是再加新的兜底。
- 不是再扩 reason 模板。
- 不是再把标签直接推回 LLM。

而是把下一步聚焦到：

```text
提高可反证证据转化率
```

## 对用户意味着什么

用户最终拿到的结果会更稳定：

- 该判错的样本更容易落到 0/1。
- 证据不足的样本会更干净地回 2。
- reason 解释会更接近真实裁决路径。

## 对开发者意味着什么

后续改动应该优先围绕：

1. 候选句如何更容易变成证据事件。
2. 证据事件如何更容易成同槽冲突。
3. 哪些题型需要更强的转换器，而不是更强的兜底。

## 当前结论

CR5-CR7 已经证明：

- 兜底权限可以统一。
- reason 可以自然化。
- debug 可以写回 ledger。

CR8 进一步说明：

> 真正还在拖住正确率的，不是“有没有兜底”，而是“候选证据能不能被稳定转换成可反证点”。

## 下一步建议

下一阶段应围绕转换率做，而不是围绕兜底做：

1. 优先补强 `candidate_unconverted -> direct_*` 的转换。
2. 对 date / numeric / phase_boundary 这类高频风险形态继续加统一转换器。
3. 再看是否需要把 `claim_planner` 或 `retrieval_diagnostics` 单独拆出来。
