# AFC改进思考记录 v4 phase4
## 题面词表去依赖改造清单

### 分类

证据链 / 检索链 / Workflow

### 这次要做什么

不是继续优化词表命中率，而是把题面词表从主链路里拆出去。

这轮先做两件事：
1. 把当前还在运行的词表按作用层分类清楚。
2. 先切掉第一批最危险的直接依赖点，让判题和 query 不再明显吃题面词。

### 动机是什么

现在很多样本能中，不是因为系统真的学会了事实核查，而是因为代码里已经埋了不少“这类题通常会出现哪些词”的先验。

这种做法短期会让个别样本变准，但会带来三个问题：
1. 换一道题就容易失效。
2. 我们很难分清是检索强了，还是词表刚好押中了。
3. 架构会越来越像题库补丁，而不是通用核查系统。

### 对项目的实际作用

把词表从主链路里降下来之后，我们才能真正看到系统缺的是什么：
- 是 query planner 不会按结构搜
- 是 candidate 转 point 不会按槽位转
- 还是 ledger / fallback 还在偷吃词面信号

这一步的价值不在于立刻涨多少样本，而在于把“真实缺口”暴露出来。

### 具体场景又是什么

像下面这些都属于题面词表风险：
- `唯一 / 必经 / 完全绕开`
- `退赛 / 不战而胜 / 3-0`
- `休市 / 高开 / 开盘`
- `开始 / 结束 / 公布`

如果系统是靠这些词决定：
- claim 是什么类型
- 应该搜什么
- 哪条证据算反证
- 没证据时该不该判错

那本质上还是押题。

### 当前活跃词表分层

#### 1. 基础设施层，可保留

这类不是押题，只是让系统少吃垃圾页：
- `retrieval.py` 里的 `ANTI_BOT_*`
- `PAGE_*_MARKERS`
- 通用 stopwords

#### 2. 检索层，当前仍有词表成分，后续要继续削弱

- `afc_route_markers.py`
- `evidence.py` 里的 route anchor / route stopwords / relation markers
- `retrieval.py` 里的 route medium hints / route frame generic skip

它们现在主要影响“搜什么”和“保留什么页”。

#### 3. 判题层，最危险，必须优先切

- `solve.py` 里的 `CORE_ASSERTION_MARKERS`
- `solve.py` 里的 `SURFACE_FACT_MARKERS`
- `retrieval.py` 里的 `ATOMIC_CLAIM_QUERY_HINTS`
- `event_semantics.py` 里的事件词表

这类如果不切，就会直接把词面带进主需次需、atomic query 或反证转换。

### 本轮已落地的第一批切断

#### A. `solve.py`

去掉了 `claim_is_core_assertion` 和 `claim_is_surface_fact` 对题面词表的直接依赖。

现在这两个判断优先看：
- `centrality`
- `answer_role_impact`
- `decision_slots`
- `evidence_mode`
- `anchor_buckets`

也就是说，核心/表层判断开始更多依赖结构，而不是“代表/意味着/开盘/汇率”这些词。

#### B. `retrieval.py`

去掉了 `ATOMIC_CLAIM_QUERY_HINTS`。

现在 atomic query 的 fallback 不再额外拼一层题面提示词，而是优先依赖：
- `subject`
- `object`
- `time_scope`
- `metric_or_relation`
- `status_or_result`
- `refutation_target.target_terms`

这一步的意义是：先逼 query planner 暴露自己到底有没有结构能力。

#### C. `event_semantics.py`

事件类词表已经集中到一个文件里，而且默认停用。

这表示：
- 词表还留作审计材料
- 但主链路默认不依赖它们

### 和前序文档的关系

这份文档接在：
- `CR9 CentralityCalibrator`
- `词表抽离与事件词表默认停用`

前一份主要是先把事件词表收起来。
这一份进一步往前走一步，开始切掉 `solve.py / retrieval.py` 里仍然会碰主链路的题面词表依赖。

### 当前结论

当前方向是明确的：

1. 基础设施词表可以留。
2. 检索辅助词表后面还要继续削弱。
3. 判题层词表必须逐步退出。
4. 退出之后，必须用结构操作符补上，不然只是“删能力”。

### 下一步建议

下一轮按优先级继续做三件事：

1. 切 `evidence.py` 里 route / calendar 的题面词表直连。
2. 把 query planner 往“槽位驱动的结构检索”推进，而不是 route marker 拼接。
3. 给 route / event / phase 三类 claim 补结构操作符，替代现有题面词表。
